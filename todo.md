# Анализ настроек CDN в Cloudflare

## Текущие правила кэширования

Я составил таблицу на основе предоставленной вами информации о настройках кэширования в Cloudflare:

| № | Название правила | Тип | Условие | Edge TTL | Browser TTL | Статус |
|---|-----------------|-----|---------|----------|-------------|--------|
| 1 | tags | URI Path | (starts_with(http.request.uri.path, "/api/collections/tag_categories/records")) or (starts_with(http.request.uri.path, "/api/collections/authors/records")) or (starts_with(http.request.uri.path, "/api/collections/tags/records")) | 1 день | 1 день | Включено |
| 2 | images | File extension | (http.request.uri.path.extension eq "webp") or ... [множество расширений файлов] | 1 год | 2 дня | Включено |
| 3 | JS cash | URI | (ends_with(http.request.uri, ".js")) | 14 дней | Не указано | Включено |
| 4 | API Collections No Cache | URI Path | (http.request.uri.path contains "/api/collections/") | Bypass cache | Не указано | Включено |
| 5 | API No Cache | URI Path | Не указано | Не указано | Не указано | Отключено |
| 6 | Cache Everything [Template] | URI Path | (not http.request.uri.path contains "/api/") | 1 год | Не указано | Включено |

## Замечания и рекомендации

1. **Отсутствующие данные**:
   - Для правила "JS cash" не указан Browser TTL
   - Для правила "API Collections No Cache" не указаны TTL (хотя указан Bypass cache)
   - Для правила "API No Cache" отсутствует условие и TTL (и правило отключено)
   - Для правила "Cache Everything [Template]" не указан Browser TTL

2. **Потенциальные конфликты**:
   - Правило "API Collections No Cache" (№4) и "tags" (№1) могут конфликтовать, так как оба относятся к путям "/api/collections/", но имеют разные настройки кэширования
   - Правило "images" (№2) и "JS cash" (№3) могут перекрываться для JS-файлов, поскольку "images" включает ".js" расширения, а "JS cash" специально нацелено на JS-файлы

3. **Рекомендации**:
   - Убедитесь, что порядок правил корректен (правила применяются сверху вниз)
   - Укажите недостающие значения Browser TTL для правил
   - Проверьте, нужно ли правило "API No Cache" (оно отключено) или его можно удалить
   - Уточните разницу между правилами для JS-файлов (они присутствуют в двух правилах с разными TTL)

    2. Проблема с лайками: почему не обновляются и как починить
Проблема
Лайки и теги на страницах (/, /profile, /game/*) не обновляются сразу, потому что:

Данные (лайки, теги) загружаются вместе с HTML-страницей через запрос к PocketBase (gamesCollection.getList).
Cloudflare кэширует HTML-страницы на 30 минут (Edge Cache TTL), поэтому даже если лайки/теги обновились в базе данных, пользователи видят старую версию страницы до истечения 30 минут.
Решение: Вынести лайки и теги в отдельные API-запросы
Чтобы лайки и теги обновлялись сразу, нужно:

Загружать данные отдельно через API:
Вместо загрузки лайков и тегов вместе с HTML (через gamesCollection.getList) делай отдельные API-запросы для каждого game:
Для лайков: /api/custom/upvotes/{gameId}.
Для тегов: /api/custom/tags/{gameId}.
Эти запросы можно выполнять в React через fetch или axios после загрузки страницы.
Отключить кэширование API-запросов в Cloudflare:
Создай правило в Cloudflare:
Условие: http.request.uri.path matches "/api/*".
Действие: Bypass cache.
Это гарантирует, что API-запросы всегда возвращают свежие данные.
Обновить код React:
В GameCard.tsx добавь useState и useEffect для загрузки лайков и тегов:
